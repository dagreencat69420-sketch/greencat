## Findings

| ID | Severity | Area | Description | Status |
|---|---|---|---|---|
| CF-01 | Medium | Program: Cat Fight `set_round_times` | After bets were in, the admin **or the operator** could still move `close_ts` (only `open_ts` was locked). That breaks the spec ("move times only before bets") and gives an insider a last-bettor edge: bet the thin side, then cut betting to `now + 60 s` so nobody can rebalance. It also let them stretch a round with user money to the 35-day limit. `docs/CATFIGHT.md` even documented it as allowed. Reproduced on a localnet binary byte-identical to the Devnet program. **Fix:** `require!(!has_bets, InvalidRoundTimes)` (same error code, no ABI/IDL change). Interim mitigation: the /admin panel disables "Update times" once a round has bets, and `npm run catfight -- times` refuses. | **fixed + deployed** (code `871b10b`; live on Devnet since the combined CF upgrade, Oct 8 2:06 AM PT, tx `fFUHnkZi…sDVj`) |
| CH-01 | Medium | API: chat display names | The reserved-name check was a plain regex, so look-alike names passed: `ADMlN`, `Adm1n`, `4dm1n`, `0fficial`, `Gr33nCat`, `G R E E N C A T`, `5upport`, Cyrillic `ВОТ`, `mod_squad`, `the mods`, plus mixed Latin + Cyrillic/Greek names. Someone could pose as the team in chat (the admin badge helps, but scammers count on people not checking it). **Fix:** confusable skeleton (Cyrillic/Greek → Latin, leetspeak digits/symbols, `l→i`), reserved substrings (admin, moderat, greencat, official, support, helpdesk, system, founder, team variants) and exact tokens (mod, mods, owner, bot), and mixed-script names are rejected. | **fixed** |
| AD-01 | Medium | Scripts: `airdrop.ts snapshot`, `airdrop-hold-check.ts` | The team exclude list only applied with `--exclude-file`. If you forgot the flag, team/treasury wallets could take top-1000 slots and real holders would lose them. **Fix:** `scripts/airdrop-exclude.json` is loaded by default (`--no-exclude-file` to opt out); the list size and file are logged and written to `rules` in the output. | **fixed** |
| CH-02 | Low | API: chat link filter | Ways around the link/scam filter: ideographic/full-width/middle dots (`。 ． ｡ · ・`), full-width or circled letters (`ｓｃａｍ．ｃｏｍ`, `ⓢⓒⓐⓜ`), `scam(.)com`, `scam .com`, and full-width base58 addresses. **Fix:** each message is also checked in NFKC form with dot look-alikes mapped to `.`, plus the `(.)` and spaced-dot patterns. Normal sentences still pass (tests). | **fixed** |
| WEB-01 | Low | Web: response headers | The web app sent only HSTS, so any site could frame it (clickjacking on wallet-connect / admin buttons). **Fix:** `X-Frame-Options: DENY`, `CSP: frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy` in `next.config.mjs`. | **fixed** |
| CF-02 | Low | Program: Cat Fight VRF | If ORAO never fulfils, a round can sit in `AWAITING_VRF` forever. After `vrf_expiry_secs` the crank can only *re-request*; there is no refund path, so funds stay locked until ORAO answers. Not exploitable for profit, but it's a liveness risk. Option: after N failed re-requests (or X days), allow `status = Refund`. **Decision (owner):** permissionless refund after a timeout. **Fix:** `refund_unfulfilled_round`: once 24 h have passed since the round's *first* VRF request (stored in former reserved bytes, `first_vrf_ts`; layout unchanged) **and** the current request is expired and unfulfilled, anyone can move the round to Refund; every bettor claims their full stake with no fee. Refused while the VRF is fulfilled (`VrfAlreadyFulfilled`) or a retry is still live (`VrfNotExpired`), before the timeout (`VrfRefundNotDue`, new error 6097), and on settled/refunded rounds (`RoundNotClosed`); settle/retry after a refund → `RoundNotClosed`. The crank and the /fight page trigger it; the panel shows the refund deadline and a "Claim refund" button. | **fixed + deployed** (`bb2dc88`; Devnet program upgraded Oct 8 2:06 AM PT; attack tests: early trigger, double refund, refund after settle, settle after refund, fake VRF account, fulfilled-past-timeout) |
| CF-03 | Low | Program: Cat Fight scheduling | Admin/operator can schedule a round to open up to 35 days out. Only one round can be open, so this pauses weekly fights (no funds at risk). Fine if intended; otherwise cap the open-delay (for example 8 days). **Fix:** `schedule_round` / `set_round_times` now require open ≤ now + 8 days and close ≤ max(open, now) + 15 days (the 35-day cap from creation stays; close ≥ now + 60 s). The default weekly schedule always fits. Same checks in the SDK (`validateFightRoundTimes`), /admin and the CLI. | **fixed + deployed** (`bb2dc88`; Devnet program upgraded Oct 8 2:06 AM PT) |
| CH-03 | Low | API: chat spam | Wallets and SIWS sign-ins are free, so one person can make many wallets. Limits are per wallet and per IP (about 60 posts/min, 30 nonces/min per IP), so a botnet/VPN pool can still flood. Options: require a minimum $GC balance (or a Points level) to post, or a global slow-mode switch. **Decision (owner):** global slow mode, not a balance gate. **Fix:** server-enforced slow mode, default ON at 10 s: one message per wallet per N s plus a room-wide cap (20 messages / 10 s), checked from stored messages (survives restarts and new sign-ins) → 429 "Slow mode is on, try again in Ns." Admin toggles it and sets N / the cap in /admin → Chat moderation (`POST /chat/admin/slow-mode`, SIWS + admin check, logged; migration `004_chat_slow_mode.sql`). Composer shows "Slow mode: 10s" and a countdown. Admins are exempt. | **fixed + deployed** (`bb2dc88`; API Oct 8 2:01 AM PT, web 2:03 AM PT; live 429 verified) |
| CH-04 | Low | API: chat names | Name uniqueness compares the lowercase name, not the confusable skeleton, so someone can still copy a *regular user's* name with homoglyphs (`Bob` vs `Bоb`). Mixed-script names are now rejected, which removes the easiest way to do it. A full fix stores a skeleton column with a unique index (migration). | **open / needs-decision** (not part of the Oct 8 deploy) |
| AD-02 | Info | Scripts: `airdrop.ts` | `expiryTs` is set when the snapshot is taken, not when `create` runs, so a late `create` shortens the claim window. Covered by the launch plan (`--expiry-days 33`, see 68ec522), but keep it in mind when timing the Post root. | noted |

### Cat Fight items reviewed with no bug found
Signer/owner checks and PDA seeds on every instruction (bets from someone else's ATA, someone else's bet PDA, fake vaults,
fake `prev_round`, fake VRF account, attacker fee vault); u128 fee/payout math, `fee ≤ losing pool`, rounding dust stays in
the vault; double claim; claim on the wrong round (both ways); claim before settle; betting after close or after the VRF
request; double settle; VRF randomness is bound to the round's request seed (it can't be reused or chosen); fee vault is
withdrawable only by the Config authority (a bet-vault withdraw is rejected); permissionless claim pays the bettor's
canonical ATA and returns rent to the bettor; one-sided round = full refund, no fee; kill switch blocks new rounds/bets
but not claims/refunds.

### Chat items reviewed with no bug found
JWT `alg: none`, wrong secret, wrong `aud` / `typ`, non-wallet subject → 401; session expires after 1 h; SQL is
parameterised (SQL-looking text is stored as plain data); messages are rendered as text (no `dangerouslySetInnerHTML`),
and HTML is stored and returned verbatim, never interpreted; length and `limit` caps; bad `before` cursor → 400; every
moderation endpoint returns 403 for non-admins; admins can't be banned; banned users can't post or rename, even after a
new sign-in; CORS allows only `https://app.greencat69420.com`; unauthenticated `POST /chat/messages` → 401.
